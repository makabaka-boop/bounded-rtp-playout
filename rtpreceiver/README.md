# rtpreceiver

限定配置的 RTP 音频接收器（Go）：通过 UDP 接收固定 12 字节头、动态载荷类型 96
的 RTP 包，每包 160 个大端 PCM16 采样、8 kHz 时钟（20 ms/帧），在可控时钟
驱动下按 20 ms 节拍输出音频帧，并从**实际输出记录**生成 WAV 与缺失报告。

## 约束的 RTP 配置

| 项目 | 取值 |
| --- | --- |
| 版本 | RTPv2（其余版本拒绝） |
| 头 | 固定 12 字节，不支持扩展头（X=0）、CSRC（CC=0）、填充（P=0） |
| 标记位 | M=0（置位即拒绝） |
| 载荷类型 | 动态 PT=96（其余拒绝） |
| 载荷 | 恰好 320 字节 = 160 × 大端 PCM16 |
| 时钟 | 8000 Hz；每包 20 ms |

解析失败的数据报计入 `InvalidPackets` 并返回哨兵错误（`ErrExtension` 等）。

## 播放与缓冲模型

- **启动延迟**：每个来源（SSRC）从首包到达起 60 ms（三帧）后开始输出；
  之后由时钟每 20 ms 输出一帧。
- **可控时钟**：`Clock` 接口同时支持墙钟（`WallClock`）与测试用 `VirtualClock`
  （`Advance` 按截止时间顺序同步触发定时器）。
- **按位置入缓冲**：固定大小环形重排窗口（默认 32 包），按扩展序号取模定位，
  与到达顺序无关。
- **去重**：同一扩展序号且槽位已占用 → 计为重复包，先到者保留。
- **丢包补零**：到播放时刻槽位为空，输出 160 个零采样，并记录 `missing` 证据。
- **迟到不改写**：已过播放位置（含已补零帧）的包一律丢弃并记录 `late` 证据，
  绝不修改已经输出的采样。
- **队列上限**：相对播放游标超前 ≥ 窗口的包记录 `ahead` 拒绝；另有 RFC 3550
  A.1 的 3000/100 跳跃保护。

### 序号与时间戳跨回绕

- 序号：RFC 3550 Appendix A.1 的 16→64 位扩展（前向 dropout、回绕、
  回绕点附近迟到乱序、远端跳变拒绝），每个采集代次重置状态。
- 时间戳：32 位载荷时间戳按有符号 32 位差与高 32 位期望值扩展为 64 位，
  任意次数的 2³² 回绕（含双重回绕）都不需要额外状态。

### 采集代次

- `RestartSource(ssrc)` 取消旧代次定时器、归档其统计与证据，分配新的
  generation id；新首包重建解包器、窗口与统计。旧代次的已输出帧保留在记录器中。
- `StopSource(ssrc)` 停止当前代次；之后到达的包计入 `after_stop` 证据但不输出。
- `MaxSources` 限制同时存在的 SSRC 数量。

## 输出

WAV 与缺失报告只来自 `Recorder` 中**实际发出的帧**：

- WAV：8000 Hz / 单声道 / PCM16 小端；补零帧原样写入，时长即真实输出时长。
- 缺失报告（JSON）：连续缺失段（起止帧号、扩展序号、扩展时间戳、发射时间），
  每段附带相关 `missing`/`late`/`ahead` 证据，其余事件列入 `extraEvidence`，
  并汇总收包、重复、迟到、超前、停止后丢弃等计数。

## 命令行

```bash
go build ./cmd/rtpreceiver
./rtpreceiver -addr :5004 -out ./recordings -window 32 -start-delay 60ms
# Ctrl-C（SIGINT/SIGTERM）后每个采集代次输出一个 WAV 和一个 *_missing.json
```

## 测试

```bash
go test -race ./...
```

测试全部使用虚拟时钟注入，覆盖：

- 60 ms 启动延迟与 20 ms 稳定节拍；
- 窗口内乱序按位置入缓冲、重复去重（播放前/播放后）；
- 丢包补零、证据链、迟到原包不得改写补零帧；
- 16 位序号单/双重回绕、回绕点两侧乱序、32 位时间戳单/双重回绕；
- 接收窗口上限拒绝；
- 停止后迟到数据、重开后独立新采集代次；
- 真实墙钟下的多源并发（`-race`）与 UDP 回环端到端。
